BIGTRANSLATE

Distributed machine translation
for large TSV corpora

THE PROBLEM

LARGE EMPLOYMENT CORPORA

The DARPA XDATA Employment dataset is a large TSV corpus of Latin American job listings from Computrabajo. Individual country-day files hold thousands of records; the collection as a whole was used to exercise analytics at a scale of tens to hundreds of millions of rows.

MIXED LANGUAGE AT SCALE

Listings mix Spanish and English in fields such as title, salary, job type, duration, and how to apply. Sending each field out to a hosted translation API does not finish in a reasonable time once the corpus grows to millions of translations.

NEED FOR QUERYABLE TRANSLATIONS

Analysts need more than a translated file. After the columns are rendered into English, the records have to be searchable and aggregable so employment trends across countries and dates can be queried at scale.

WHAT IS BIGTRANSLATE?

A distributed, parallelized (Map Reduce) system that uses Pantogloss — a TensorFlow/Keras many-to-English library that runs locally, with no hosted translation APIs — to machine-translate TSV corpora. BigTranslate uses Mnemosyne — the continuation of Apache OODTTM after the ASF retired it to the Attic in 2023 — to split and workflow those translations across many millions of rows. It has been tested on up to 190 million rows on 16-core nodes.

TSV in, JSON out

BigTranslate uses ETLLib to turn Computrabajo-style TSV into JSON job records, then translates selected columns — title, salary, job type, duration, start, applications, and department.

Pantogloss, with a glossary

Pantogloss runs a local many-to-English model offline. A Spanish→English employment glossary and translation cache correct systematic terms such as Tiempo Completo, Inmediato, and Correo Electrónico.

Index into Solr

Translated JSON is posted to Apache SolrTM so the corpus can be queried, faceted, and analyzed after the Map Reduce run completes.

HOW IT WORKS

The workflow follows the XDATA Employment data bible: a country-day TSV is ingested, exploded into one JSON document per job, translated, and archived.

1

Ingest & partition

The crawler picks up files such as computrabajo-do-20121106.tsv from staging. A TsvToJson PGE splits the aggregate file into individual job JSON documents — the Map Reduce partitioner.

2

Translate columns

pantogloss-translatejson runs as a PGE over the job directory, translating the configured columns from Spanish to English with the glossary as an authoritative override and a cache so re-runs skip strings already translated.

3

Reduce into Solr

Translated JSON is posted to Solr. Original TSV, aggregate JSON, per-job JSON, and translated JSON all land in the archive so a country-day can be re-run or inspected later.
